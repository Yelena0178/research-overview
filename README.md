## 我负责维护的内容

- **项目索引**：项目名称、核心数学或物理问题、研究领域和源仓库入口。
- **进展摘要**：本次相较上次核对新增了什么，以及信息来自哪些文件与版本。
- **当前障碍**：原项目明确记录的证明缺口、缺少的输入或其他阻塞事项；未说明时标为待核对。
- **下一步安排**：区分用户安排、原仓库计划和我的建议，避免将建议写成已决定事项。
- **可追溯记录**：保留核对日期、源仓库提交、阅读范围和简短进展历史。

重点关注数学物理、广义相对论、量子场论、黑洞、弦论与 AdS/CFT Correspondence（AdS/CFT 对应）等研究。每个项目以自己的精确问题和来源为准。

## 如何使用

| 你提出的需求 | 我在这里做的工作 |
| --- | --- |
| “把这个项目加入总览” | 读取指定仓库，建立项目进度卡并更新总表。 |
| “更新这些项目的进度” | 对照上次记录，核对源仓库变化，更新摘要、障碍和下一步。 |
| “现在有哪些项目卡住了” | 根据已记录并标明核对时间的材料，汇总阻塞点与需要决定的事项。 |
| “这周重点看这个项目” | 更新当前重点，注明用户安排；具体研究仍在源仓库开展。 |

按任务更新时，我会读取相关源仓库。没有实际核对的内容标为未核对；这里的更新不代表已经运行持续监控或定时同步。

## 如何理解研究成果

摘要会保留原结果的假设与适用范围，区分猜想、条件性结论、计算证据和原仓库报告的证明。普通进度更新只说明实际阅读与核对的范围，不构成完整的数学审查；涉及独立审查的结论须指向相应报告。
