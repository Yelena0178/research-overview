# 项目索引与进度卡

本目录由助手维护各研究项目的简要索引和进度。**具体研究及其权威文件始终留在各自源仓库**；这里仅保存摘要和链接，不复制论文、推导或代码，不生成研究执行环境。更新本总览不构成修改源仓库的授权。

## 登记方式

1. 在用户指定需要纳入总览的项目后，读取其源仓库，确认名称、问题和已有记录。
2. 将[单页模板](_template/README.md)复制为 `projects/<project-slug>/README.md`，填写实际查到的信息。
3. 同步更新[根目录总览](../README.md)，使项目名、阶段和进度卡链接保持一致。

模板不计为项目；不依据历史记忆自动导入项目，未知信息明确写“待核对”或“未指定”。

## 维护内容

每张进度卡记录项目名、源仓库、核心问题、领域、阶段、用户指定优先级、源仓库报告的成果、实际阅读与核对范围、当前障碍、下一步、核对日期和源提交 SHA，以及少量关键证据链接和简短进展历史。

下一步应标明来源为“用户安排”“原仓库计划”或“助手建议”；建议不应写成已确定的项目安排。优先级只记录用户的明确指定。

## 阶段与结论可信度

| 阶段 | 含义 |
| --- | --- |
| 待核对 | 尚未取得足以判断当前进度的信息 |
| 研究中 | 项目正在推进问题分析、推导或验证 |
| 受阻 | 存在有记录的关键障碍 |
| 撰写中 | 正在组织论文或报告 |
| 投稿准备中 | 正在准备投稿材料 |
| 暂停 | 项目明确暂停推进 |
| 归档 | 项目已归档，具体原因在卡片中说明 |

阶段描述工作进度，不表示数学结论已获证明。成果使用“原仓库报告……”的措辞，并另写实际读过或核对过的文件、章节及范围；仅查看摘要、局部推导或程序输出时，不扩展为完整证明已获独立验证。提交次数不能单独衡量数学进度。

## 更新与追溯

每次实质更新记录核对日期和源提交 SHA，证据尽量链接到对应提交下的文件或准确章节。保留简短的变化及其依据；未取得源提交时如实说明。源仓库发生变化后，摘要须重新核对，冲突以源仓库的实际文件为准。
